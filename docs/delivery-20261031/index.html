100% de una versión definida

Una versión está terminada cuando sus capacidades incluidas funcionan, se recuperan de fallos y una persona puede operarlas en el entorno acordado.

  • Alcance y criterios reconciliados: los documentos antiguos mezclan roles, negocios y sucursales.
  • Recorridos completos UI → API → persistencia, incluidos permisos y errores.
  • Integridad, concurrencia, replay y recuperación demostrados en el candidato exacto.
  • Operación privada, soporte y reversión probados; rendimiento y accesibilidad medidos.
  • Martha o el operador completa las tareas y acepta utilidad y presentación.

Cómo se aceptaría un trigger futuro

Un fallo sintético debe generar exactamente un evento y un worker. Repetir el evento no duplica trabajo. Tiempo, permisos, modelo, gasto y parada deben estar definidos. El resultado vuelve a un revisor; no autoriza despliegue automático.
