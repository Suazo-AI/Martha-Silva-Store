Qué vamos a comprobar

Los primeros cuatro métodos fallaron por problemas del entorno de pruebas o su verificador. La corrección pasó revisión independiente; falta ejecutarla con SQL.

1. Impedir que una cuenta vea operaciones ajenas.

Caso ficticio: una persona registra una venta en la sucursal A. Después se cambia su asignación a la sucursal B.

Comprobación: el sistema consulta la sesión y los permisos guardados antes de devolver el resultado. Otro actor tampoco puede recuperar esa operación.

Pasa si devuelve el resultado al actor permitido y rechaza los accesos posteriores sin revelar la venta.

Evita que una sesión conserve acceso que ya no le corresponde. La autenticación del test es sintética; el endpoint y SQL son reales.

Martha.Store.Api.Tests.InternalBranchScopeSqlTests.BS21_25_Operations_http_checks_persisted_scope_and_actor_before_returning_result
2. Impedir que un cajero vea costos de compra.

Caso ficticio: un cajero intenta consultar pedidos de compra y sus recepciones mediante tres rutas del sistema.

Pasa si las tres respuestas rechazan el acceso y ninguna incluye el campo del costo unitario.

Protege información de compras. Una pantalla que oculta el costo no basta: el servidor también debe impedir su lectura.

Martha.Store.Api.Tests.InternalBranchScopeSqlTests.BS28_Cashier_cannot_read_purchase_costs_through_any_supply_get
3. Instalar y actualizar la estructura sin perder la muestra.

Caso ficticio: instalamos SAVIA en una base vacía. También actualizamos una base que solo tiene la primera versión.

Pasa si ambas llegan a la estructura esperada y la actualización conserva las filas ficticias verificadas.

Comprueba el script de actualización. No actualiza ninguna base existente de tu equipo.

Martha.Store.Api.Tests.InternalReleaseScriptTests.Release_script_upgrades_empty_and_first_migration_databases_and_preserves_synthetic_rows
4. Crear un backup y restaurarlo en otra base temporal.

Caso ficticio: guardamos el artículo QA-PILOT-01, precio USD 12.50, con 17 unidades y 3 reservadas.

El método verifica migraciones, reaplicación y una reversión en otra base desechable. Después crea un backup con checksum y lo restaura.

Pasa si coinciden estructura y las cuatro proyecciones de datos básicos verificadas antes y después de restaurar.

La reversión destruye exclusivamente su fixture temporal. No representa un procedimiento de recuperación para datos reales.

Qué cambia en tu PC

Dentro del alcance propuesto

  • Un contenedor: un servidor de prueba aislado.
  • SQL Server 2022 Developer, 2 CPU y 2 GiB de RAM.
  • Puerto 127.0.0.1:14339, accesible desde tu PC.
  • Bases nuevas SaviaInternalTest_* y datos ficticios.

  • Datos del servidor en su almacenamiento temporal, sin carpetas del host montadas.

Fuera del alcance

  • SQL nativo y bases preexistentes.
  • Cuentas, clientes, ventas o dinero reales.
  • Certificados de Windows y confianza global.
  • Cambios en firewall, servicios o cuentas del equipo.
  • Descargas, instalaciones, merge y despliegue.
  • Reparar código y volver a ejecutar sin un nuevo alcance.

Podría consumir CPU, memoria y disco mientras corre. Si falta una herramienta, el motor no responde o el puerto está ocupado, se detiene la preparación.
