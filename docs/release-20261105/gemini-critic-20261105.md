- **Ubicación exacta:** `docs/release-20261105/responsive-integration/DRIVER-CORRECTION.json:4`, `docs/release-20261105/responsive-followup/driver.mjs:8-10` y `docs/release-20261105/responsive-integration/IMPORT.json:9-12,5900-5920`.

En un worktree limpio con `core.autocrlf=true` (`t3-84d747c8`), Git entrega las 57 líneas como `CRLF` (15,412 bytes, SHA256 RAW `0f9e90c1cabf04bc5850f74b437931de17aca24f869f8e45d95c98adf41d9383` y SHA256 LF/blob Git `0fbc59408070b12d0698d187703763f3dda14db7261f7f7df810dc2c4d434225`). Análogamente, 7 archivos de texto en `IMPORT.json` (`build-inputs/README.md`, `tests/responsive_images.py`, `tools/responsive_images.py` y 4 scripts en `docs/release-20261105/responsive-images/`) tenían saltos mixtos `CRLF`/`LF` en el worktree del worker `t3-3e335278`, por lo que su SHA256 RAW importado no coincide con el checkout `CRLF` uniforme aunque el texto normalizado a `LF` es idéntico byte por byte al blob de Git (`HEAD`).
- **Comprobación o corrección mínima reproducible:** Verificar igualdad sobre bytes normalizados a `LF` (`bytes.replace(b'\r\n', b'\n') == git_blob_bytes`) e incluir `lfSha256` junto a `rawSha256` en recibos futuros de corrección/importación, tal como ya hace `BASELINE-IMPORT.json:3`.
