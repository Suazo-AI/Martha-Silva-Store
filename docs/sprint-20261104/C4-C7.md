### Pruebas nuevas (`InternalReleaseScriptTests.cs`)

- `Checked_in_idempotent_release_script_equals_ef_generation_for_every_internal_migration` (sin SQL):
  exige que el archivo registre cada migración de `GetMigrations()` y que sea igual a
  `GenerateScript(options: Idempotent)`, tolerando solo BOM, CRLF y saltos finales. Además rechaza
  `CREATE/ALTER/DROP DATABASE`, `USE`, logins y usuarios. El mensaje de fallo incluye el comando para regenerar.
- `Release_script_upgrades_empty_and_first_migration_databases_and_preserves_synthetic_rows`
  (`[InternalSecuritySqlFact]`), con tres bases `SaviaInternalTest_Release_<guid>` que siempre se eliminan en `finally`:
  1. Base vacía + script por lotes `GO` → `__EFMigrationsHistory` = ambas migraciones; nombres de tablas,
     checks, FK, índices y PK iguales al oráculo derivado del modelo
     (`backend/tests/fixtures/expected-invariants.model-derived.json`); restricciones habilitadas y confiables.
  2. Otra base con el migrador real de EF → mismos hechos de esquema, incluidas columnas, definiciones de
     checks y columnas de índices.
  3. Base con **solo** `InitialInternalSavia` (migrador EF hasta esa migración) y filas sintéticas en 9 tablas
     (artículo, ubicación, Cashier, sesión, saldo, venta, línea, movimiento, operación) → script → historial
     con ambas migraciones; cada fila de cada tabla previa, con sus columnas previas y `RowVersion`, idéntica;
     columnas nuevas de alcance en `NULL` y `Branches`/`BranchAssignmentAudit` vacías (sin asignación inferida
     ni backfill); esquema igual al de la base vacía. Reaplicar el script no cambia historial, esquema ni filas.
