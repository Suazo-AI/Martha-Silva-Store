Why a native wrapper is not automatic

SAVIA uses HttpOnly, Secure, SameSite=Strict cookies, CSRF and same-origin requests. Moving the interface into a native origin requires its own authentication proof. The proposal preserves the current protections.

First-slice acceptance proposal

Expand each item to inspect the required proof. No item is marked complete by this review.

M01–M02 · Login and stock

Real login/logout on both phones. Anonymous requests denied. Server stock and location match the screen. Logout, expiry and 401 remove protected data.

M03–M05 · One sale, one durable result

Server receipt and stock movement survive reload. Double tap and retry cause no duplicate debit. A lost response can be recovered after reload with the original operation identity.

M06–M07 · Offline and permissions

Offline mode blocks business writes and never invents success. Protected responses are not cached. Direct API requests enforce role and branch limits.

M08–M10 · Phones and regressions

Install, reopen and resume on an actual iPhone and Android. Check narrow layouts, touch, keyboard and accessibility. Preserve existing staff/store behavior and provide original before/after recordings for visual review.
