Base: `Tony@1a2620e`. Sources: [PLAN](../PLAN.md), [AZURE](AZURE.md), [CHECKLIST](CHECKLIST.md), `savia/src`, `savia/db/migrations`.
Scope: the SAVIA v2 backend in `savia/`. The old `backend/` (Martha.Store) and the pilot v1 are not in this plan.

## Result

The SAVIA hub runs in Azure (`rg-savia-prod`, `mexicocentral`) on commit `9a55759`: 30 migrations applied, smoke test passed, readiness 200.
No store connects to it yet: the P9 sync transport is built and tested locally (V032-V034), but the hub image in Azure predates it and no store has a node credential.
The first try failed because `mexicocentral` refuses geo-redundant SQL backups, so backups are now `Zone`.
The backend is not complete: the sync transport is built but not deployed, and recovery after a store restore still needs the recovery lock.
