## Actual source review

Customer filters and inactive flag are preserved in transport; UI currently uses active records by default.
2. Both connected directory views provide previous/next controls, page-size25/50/100 and confirmed range/total text. Each retains its own applied query and pagination state. New searches and size changes reset offset0. Dirty, unapplied query text cannot be mixed with a previous offset. The server's skip ceiling is respected and explained rather than silently loading beyond it.
3. Failed reads clear rows and confirmed pagination, show an error rather than an empty-directory success, disable pager controls, and leave search available to recover. Loading disables incompatible controls; empty pages beyond a reduced total are handled without inventing records. Pagination sends GET only and does not enable writes.

Late success cannot restore private rows. Both the existing DOM regression and the new integrated transport+DOM regression pass.
5. Added row/range/query text uses textContent, not HTML interpolation. No external runtime origin, credential default, synthetic business fallback, idempotency mutation or business write was added. Auth/login module and its CSRF/direct-me/204 contract behavior are unchanged.

No new P1/P2 was found in the pagination delta. That statement is limited to the inspected source and executed double-based cases, not an exhaustive vulnerability or accessibility audit.
